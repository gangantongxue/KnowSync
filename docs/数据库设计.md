# KnowSync 数据库设计

> KnowSync 采用多数据库设计，各微服务拥有独立的 MySQL 数据库实例，遵循微服务数据隔离原则。

## 一、设计原则

1. **禁止数据库外键约束**：字段保留逻辑引用（如 `user_id`、`repo_id`），但不在数据库层面设置 `FOREIGN KEY`
2. **禁止 JOIN 查询**：多表关联时在 service 层组合数据
3. **主键策略**：用户 ID 使用数字自增（转为字符串）；其他实体使用 xid（20 字符，全局唯一，按时间排序）
4. **软删除**：支持逻辑删除的表使用 `deleted_at` 字段 + GORM `DeletedAt` 类型
5. **时间戳**：GORM `autoCreateTime` / `autoUpdateTime` 自动管理

## 二、数据库划分

| 服务 | 数据库名 | 表数量 |
|------|---------|--------|
| user-server | `knowsync_user` | 2 |
| repo-server | `knowsync_repo` | 3 |
| ai-server | `knowsync_ai` | 2 |
| chat-server | `knowsync_chat` | 6 |
| **合计** | | **13** |

## 三、user-server 数据库 (`knowsync_user`)

### 3.1 `user` — 用户表

用户账户信息存储表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | varchar(20) | PK | 用户 ID（数字自增转字符串） |
| `name` | varchar(64) | NOT NULL | 用户名 |
| `email` | varchar(254) | NOT NULL, UNIQUE | 邮箱地址（登录凭证） |
| `password` | varchar(255) | NOT NULL | bcrypt 加密密码 |
| `avatar` | varchar(255) | | 头像 URL |
| `created_at` | datetime | NOT NULL | 创建时间 |
| `updated_at` | datetime | NOT NULL | 更新时间 |
| `deleted_at` | datetime | INDEX | 软删除时间 |

**索引**：
- `idx_user_email` — `email` 唯一索引
- `idx_user_deleted_at` — `deleted_at` 普通索引

### 3.2 `user_session` — 用户会话表

用户登录会话记录，用于 refresh token 管理。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | char(20) | PK | 会话 ID（xid） |
| `user_id` | varchar(20) | NOT NULL, INDEX | 用户 ID |
| `refresh_token_hash` | varchar(255) | NOT NULL | Refresh Token 的 SHA-256 哈希值 |
| `client_ip` | varchar(64) | NOT NULL | 登录时的客户端 IP |
| `expire_at` | datetime | NOT NULL | 会话过期时间 |
| `login_at` | datetime | NOT NULL | 登录时间 |
| `logout_at` | datetime | | 登出时间 |
| `created_at` | datetime | NOT NULL | 创建时间 |
| `updated_at` | datetime | NOT NULL | 更新时间 |
| `deleted_at` | datetime | INDEX | 软删除时间 |

**索引**：
- `user_id_refresh_token_hash_index` — `(user_id, refresh_token_hash)` 唯一复合索引
- `idx_user_session_user_id` — `user_id` 普通索引
- `idx_user_session_deleted_at` — `deleted_at` 普通索引

## 六、chat-server 数据库 (`knowsync_chat`)

### 6.1 `users` — 聊天用户缓存表

> 从 user-server 同步的用户数据缓存，用于聊天模块的用户搜索。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | varchar(20) | PK | 用户 ID |
| `name` | varchar(50) | NOT NULL | 用户名 |
| `email` | varchar(100) | NOT NULL, UNIQUE | 邮箱 |
| `avatar` | varchar(255) | DEFAULT '' | 头像 URL |
| `password` | varchar(255) | NOT NULL | 密码（JSON 中隐藏） |

**索引**：
- `idx_users_email` — `email` 唯一索引

### 6.2 `friends` — 好友关系表

> 双向存储：好友关系会为双方各插入一条记录，方便各自独立查询好友列表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | char(20) | PK | 记录 ID（xid） |
| `user_id` | varchar(20) | NOT NULL | 用户 ID |
| `friend_id` | varchar(20) | NOT NULL | 好友用户 ID |
| `remark` | varchar(100) | DEFAULT '' | 好友备注 |
| `last_message_at` | bigint | NOT NULL, DEFAULT 0 | 最后消息时间戳 |
| `last_read_seq_id` | bigint unsigned | NOT NULL, DEFAULT 0 | 已读的最大消息 SeqID |
| `pinned` | tinyint(1) | NOT NULL, DEFAULT 0 | 是否置顶：0 否 / 1 是 |
| `created_at` | bigint | NOT NULL | 成为好友的时间 |

**索引**：
- `uk_user_friend` — `(user_id, friend_id)` 唯一复合索引

### 6.3 `friend_requests` — 好友申请表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | char(20) | PK | 记录 ID（xid） |
| `sender_id` | varchar(20) | NOT NULL, INDEX | 发送方用户 ID |
| `receiver_id` | varchar(20) | NOT NULL, INDEX | 接收方用户 ID |
| `status` | enum('pending','accepted','rejected') | NOT NULL, DEFAULT 'pending' | 申请状态 |
| `remark` | varchar(100) | DEFAULT '' | 申请附言 |
| `created_at` | bigint | NOT NULL | 发送时间 |
| `updated_at` | bigint | NOT NULL | 处理时间 |

**索引**：
- `idx_sender` — `sender_id` 普通索引
- `idx_receiver_status` — `(receiver_id, status)` 复合索引（用于查询待处理的申请）

### 6.4 `messages` — 消息表

> 统一存储私聊和群聊消息，通过 `conversation_type` 区分。系统邀请消息也使用此表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | char(20) | PK | 消息 ID（xid） |
| `conversation_type` | enum('private','group') | NOT NULL | 会话类型 |
| `conversation_id` | varchar(64) | NOT NULL, INDEX | 会话 ID（私聊为双方 ID 排序拼接，群聊为 group_id） |
| `seq_id` | bigint unsigned | NOT NULL, INDEX | 会话内单调递增序列号 |
| `sender_id` | varchar(20) | NOT NULL, INDEX | 发送方用户 ID |
| `content_type` | enum('text','image','file','system_invitation') | NOT NULL, DEFAULT 'text' | 消息内容类型 |
| `content` | text | NOT NULL | 消息内容 |
| `extra` | json | | 扩展数据（如文件元信息） |
| `reply_to_id` | char(20) | | 回复的消息 ID |
| `status` | enum('normal','recalled') | NOT NULL, DEFAULT 'normal' | 消息状态 |
| `created_at` | bigint | NOT NULL | 发送时间 |

**索引**：
- `idx_conversation` — `(conversation_id, seq_id)` 复合索引（用于消息分页查询）
- `idx_sender` — `sender_id` 普通索引

### 6.5 `groups` — 群组表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|

|------|------|------|------|

## 八、索引设计要点

1. **复合索引优先**：消息查询按 `(conversation_id, seq_id)` 复合索引定位，避免全表扫描
2. **状态过滤索引**：好友申请表的 `(receiver_id, status)` 复合索引覆盖"查询某人待处理的申请"场景
3. **唯一约束替代业务校验**：`(repo_id, user_id)` 唯一索引防止重复添加协作者
4. **反向查询索引**：好友关系双向存储，各自独立查询无需 JOIN
5. **软删除不影响查询**：`deleted_at` 索引确保软删除过滤不走全表扫描
